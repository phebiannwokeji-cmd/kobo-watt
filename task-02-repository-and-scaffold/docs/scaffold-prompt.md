## Final version

Read the project’s business brief, supporting decisions, Task 1
design-system documentation, generated token files, and applicable
repository instructions before making changes.

Summarise your understanding of Kobo Watt, its intended customer,
the design system, and the scaffolding scope. Identify assumptions,
contradictions, and missing information.

Separate technical choices already recorded in the documentation from
choices you are proposing. Explain why each proposed choice fits.
Describe the files you expect to create or modify and how the application
will use the existing design-system files.

Before approval, only inspect existing files and report your plan.
Do not create or modify files, install dependencies, or run scaffolding
commands until I approve.

Treat the supplied business context and design-system files as the
source of truth. Ask when important instructions conflict or a required
decision is missing, rather than guessing.

Use the existing design-system tokens and typography styles. Do not
invent hardcoded styling values. If a required token is missing,
explain the gap and propose a solution before proceeding.

After approval, build only the project setup and a minimal home screen
inside task-02-repository-and-scaffold.

The minimal home screen should contain:
The Kobo Watt name.
A main heading: “Power for your business”.
One short explanation of the service, based on the business brief.
One “View demo account” link or button.
A clear demonstration-only notice.

Explain how the demo link will work without modifying Task 1.
Do not add other product features without discussing them with me.
Do not build the full product or change the completed Task 1 files.

After implementation, list every file created or modified, every
assumption made, and any unresolved issues.

Run the application and report the exact start command and actual
result. If it fails to start, report the failure honestly.

Before finishing, review your work against every instruction above.
Report anything you did not satisfy.

## What changed and why

I made the home-screen scope explicit and strengthened the approval
boundary to include file changes, dependency installation, and
scaffolding commands. I also asked the agent to distinguish existing
technical decisions from proposals and explain how the demo link and
design-system files will work. These changes help me review the plan
before implementation begins.
