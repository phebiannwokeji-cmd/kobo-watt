5. Layout values: verified versus proposed

Verified in Task 1 prototype/screen.css:
- Page maximum width: 30rem.
- Page horizontal padding: 16px.
- Existing spacing values include 8px, 12px, 16px, and 24px.
- Card and button radius: 8px.
- Button padding: 10px vertically and 16px horizontally.
- Border width: 1px.
- Focus outline: 3px, with a 2px offset.
- Existing buttons also have min-height: 48px.

New Task 2 proposal:
Convert the selected spacing and radius values into rem-based local
tokens. These are new definitions, not existing Task 1 tokens.

At a 16px root font size, the proposed values correspond to the
verified pixel values. They grow if the root font size changes.
Do not force the root font size to 16px.

Proposed tokens:
--kw-layout-max-width: 30rem
--kw-layout-space-small: 0.5rem
--kw-layout-space-medium: 0.75rem
--kw-layout-page-padding: 1rem
--kw-layout-section-gap: 1.5rem
--kw-layout-button-padding-block: 0.625rem
--kw-layout-button-padding-inline: 1rem
--kw-layout-radius: 0.5rem
--kw-layout-border-width: 1px
--kw-layout-focus-width: 3px
--kw-layout-focus-offset: 2px

Reasons:
- Page padding keeps content away from screen edges.
- Section gaps separate the heading, explanation, link, and notice.
- Button padding gives its words surrounding space without fixing
  the control’s dimensions.
- Radius retains Task 1’s rounded appearance at the default root size.
- Border and focus values retain the existing visual treatment.

Do not add control-min-height.
Do not give the demo link a fixed width or height.
Allow its words to wrap and its box to grow.
Keep its width within the available page space.

Store these definitions in Task 2’s layout-tokens.css.
Component rules must reference them.
Structural values such as zero margins and percentage widths are
layout instructions, not additions to the spacing scale.

6. Serving the existing demo

Use one Express server bound to 127.0.0.1.
Default port: 3000; optionally overridden by PORT.

Check port availability at startup.
If occupied, report the error. Do not terminate an existing process.

Serve Task 1 through fixed file routes:
- /demo -> redirect to /demo/
- /demo/ and /demo/index.html -> prototype/index.html
- /demo/help.html -> prototype/help.html
- /demo/help-no-power.html -> prototype/help-no-power.html
- /demo/screen.css -> prototype/screen.css
- /demo/demo.js -> prototype/demo.js
- /styles/fonts.css -> styles/fonts.css
- /styles/tokens.css -> styles/tokens.css
- /styles/typography.css -> styles/typography.css
- The two specific /fonts/SourceSansPro-SemiBold-*.woff2 URLs
  -> their corresponding font files.

Enable strict routing before registering routes so /demo and /demo/
can be distinguished.

Resolve file paths from the server file’s directory, not from whichever
directory the terminal happens to be using.

Use fixed absolute paths with sendFile.
Do not accept user-supplied filesystem paths.

Task 2:
- / serves its home page.
- /assets/layout-tokens.css serves its local layout tokens.
- /assets/home.css serves its home styling.

Use explicit file routes for these assets too.
Unknown URLs return 404.

Do not serve the repository root, Git metadata, docs, evidence, tools,
JSON exports, or directory listings.

Do not copy, rewrite, or symlink Task 1.
